#2
Seek bar drag value not reset on track change
📁 player_panel.dart → _SeekBarState._dragValue
High ▾

Root cause: _dragValue is local state in _SeekBarState. If the user starts dragging and a track switch occurs (prev/next), _dragValue remains non-null. The clamp(0, max) call masks this but if the old drag value exceeds the new track's duration, the displayed position is incorrect until the user releases the seek.

// ✅ FIX — add BlocListener to reset drag on track change
class _SeekBarState extends State<_SeekBar> {
  String? _currentTrackId;
  double? _dragValue;

  @override
  Widget build(BuildContext context) {
    return BlocListener<PlayerBloc, PlayerState>(
      listenWhen: (prev, curr) => prev.track?.id != curr.track?.id,
      listener: (_, __) => setState(() {
        _dragValue = null;   // clear stale drag on track change
      }),
      child: BlocBuilder(...),  // existing seek bar builder
    );
  }
}
#3
SafeArea adds incorrect bottom padding in two-pane layout
📁 player_panel.dart → _PanelContent
Medium ▾

Root cause: _PanelContent wraps everything in SafeArea(top: false) which adds the home-indicator bottom inset on iPhone. In the two-pane layout, PlayerPanel is rendered inside a Column that occupies the right rail — not the bottom edge of the screen. The SafeArea adds unnecessary whitespace there, making the panel taller than needed.

#4
Two-pane _PlayerPane layout jump when track is absent
📁 search_screen.dart → _PlayerPane
Medium ▾

Root cause: _PlayerPane uses Column(mainAxisAlignment: MainAxisAlignment.end). When no track is loaded the EmptyStateView shows. When a track is loaded, PlayerPanel replaces it at the bottom with AnimatedSize. The empty state and player fight for vertical space, causing a layout jump on first load.

// ✅ FIX — stack: empty state fills space, panel anchored to bottom
class _PlayerPane extends StatelessWidget {
  const _PlayerPane();
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        Expanded(
          child: BlocSelector<PlayerBloc, PlayerState, bool>(
            selector: (s) => s.hasTrack,
            builder: (ctx, hasTrack) => AnimatedSwitcher(
              duration: const Duration(milliseconds: 300),
              child: hasTrack
                ? SizedBox.shrink(key: const ValueKey('empty'))
                : EmptyStateView(key: const ValueKey('hint'), ...),
            ),
          ),
        ),
        PlayerPanel(isBottomBar: false),
      ],
    );
  }
}

#6
Speed chip popup can appear off-screen on small devices
📁 player_panel.dart → _SpeedChip.onLongPress
Medium ▾

Root cause: The popup's top position is computed as offset.dy - speeds.length * 48.0, which can be negative when the player is near the top of the viewport (e.g., two-pane layout). Flutter's showMenu does not auto-clamp negative positions.

// ✅ FIX — use MediaQuery to clamp popup position
final screen = MediaQuery.sizeOf(context);
final menuHeight = speeds.length * 48.0;
final top = (offset.dy - menuHeight)
    .clamp(8.0, screen.height - menuHeight - 8.0);

await showMenu<double>(
  context: context,
  position: RelativeRect.fromLTRB(
    offset.dx,
    top,
    offset.dx + box.size.width,
    top + menuHeight,
  ),
  items: ...,
);

#8
No RepaintBoundary isolating seek bar from static controls
📁 player_panel.dart → _PanelContent
Low ▾

Root cause: _SeekBar rebuilds ~4 Hz from the position stream. Without a RepaintBoundary, the GPU composites _Header, _SeekBar, and _Controls together each tick — wasted work since header and controls are visually static during playback.

// ✅ FIX — wrap _SeekBar in RepaintBoundary
Column(children: [
  _Header(),
  SizedBox(height: 12),
  RepaintBoundary(child: _SeekBar()),  // ← isolate repaints
  SizedBox(height: 4),
  _Controls(),
])
#9
Panel corner radius inconsistent between single/two-pane layouts
📁 player_panel.dart → _PanelContent decoration
Low ▾

Root cause: _PanelContent always applies BorderRadius.vertical(top: Radius.circular(24)). In single-pane (bottom panel) this makes sense. In two-pane, the panel is in the right column mid-screen, so top-only rounded corners look visually unbalanced.

  ),
  child: ...,

Create SurahDetailPage
New file: lib/features/surah/view/surah_detail_page.dart. Full-page Scaffold with a gradient hero header (surah name, number, Arabic name, ayah count, revelation type), reciter selector chip, embedded player, and scrollable ayah list. Replaces the AyahView bottom sheet for primary reading.
Change SurahTile tap → navigate instead of play
In search_screen.dart, change onTap to push SurahDetailPage via Navigator.push(). Remove the immediate PlayerTrackSelected dispatch. Play is now only triggered when the user explicitly taps the Play button in the detail page header. Keep the surah tiles' active/playing visual indicator via PlayerBloc.
Embed reciter selector in detail page header
Show the currently selected reciter as a tappable chip in the surah hero header. Tapping opens the ReciterPicker bottom sheet. The selected reciter is sourced from SearchBloc.state.selectedReciter and always visible — no hidden long-press required.
Embed player panel inside detail page (not bottom overlay)
The player controls live in a sticky section at the top of the detail page (below the hero header), not as a floating overlay. This eliminates the "panel covers content" problem. The player is always contextually tied to the surah being viewed. Use SliverAppBar with the player pinned.
Improve loading state — skeleton + status text
When PlayerState.status == loading, show a shimmer skeleton on the seek bar, disable seek + speed controls, and show a "Loading audio…" text label. On error, show an inline error banner with a retry button inside the player section — not just a red error message under the track title.
Add persistent MiniPlayerBar on SearchScreen
Rename the current PlayerPanel into a compact MiniPlayerBar that shows: current surah name, play/pause button, and a progress pill. The ✕ button only collapses the bar (hides it) but does not stop playback. Add a separate Stop action inside the detail page. The mini bar appears at the bottom of SearchScreen whenever a track is active.
Auto-scroll ayah list to active verse
Using the position stream from PlayerBloc and ayah duration data, highlight and auto-scroll to the currently playing ayah. This requires either a verse-by-verse audio edition or an offset map (surah total duration / ayah count). Start with proportional approximation, upgrade later to verse-by-verse API.

📋 Implementation Steps

Create QuoteService
New file: lib/data/services/quote_service.dart. Uses existing IAyahRepository to fetch a surah, picks a random ayah, and persists it to SharedPreferences as JSON (QuoteModel) so it survives app restarts and is readable by the native widget.
Add QuoteModel
New file: lib/data/models/quote.dart. Fields: surahNumber, surahEnglishName, surahArabicName, ayahNumber, arabicText, translation, generatedAt. Serializable to JSON for SharedPreferences + native widget.
Create NotificationService
New file: lib/data/services/notification_service.dart. Wraps flutter_local_notifications. Methods: initialize(), scheduleDaily(hour, minute), scheduleTimes(List<TimeOfDay>), cancelAll(), showImmediate(QuoteModel).
Create QuoteBloc
New file: lib/features/quote/bloc/quote_bloc.dart. Events: QuoteLoadRequested, QuoteRefreshRequested, QuoteScheduleChanged. State fields: quote, status, schedule (enum: off / morning / evening / 3x / custom), customTimes.
Build QuoteCard widget
New file: lib/features/quote/view/quote_card.dart. Full-width card with gradient background, Arabic text (Scheherazade New font), translation, surah/ayah badge, "Read Surah" and "Share" actions. Accessible via a dedicated button in SearchHeader or Settings.
Add Notification Settings section
Extend lib/features/settings/view/settings_screen.dart with a new "Daily Reminders" section. Toggle to enable/disable, schedule picker (Morning 7am / Evening 7pm / 3× day / Custom), and a "Preview quote" button that calls NotificationService.showImmediate().
Handle notification tap → deep link
In main.dart / app.dart, handle onDidReceiveNotificationResponse to extract the payload (surah number) and call AyahView.show() or navigate to the quote card. Register NotificationService.initialize() before runApp().
Request & handle permissions
iOS requires requestPermissions() on first launch. Android 13+ requires POST_NOTIFICATIONS permission. Show a rationale dialog before requesting. Store permission state in AppSettings via SettingsBloc.

📋 Implementation Steps

Add home_widget package
Add home_widget: ^0.6.0 to pubspec.yaml. This bridges Flutter ↔ native with a shared UserDefaults (iOS) / SharedPreferences (Android) storage group. No platform channel boilerplate needed.
Create WidgetDataService
New file: lib/data/services/widget_data_service.dart. Calls HomeWidget.saveWidgetData() for keys: quote_arabic, quote_translation, quote_surah, quote_ayah_num, now_playing_surah. Then calls HomeWidget.updateWidget().
iOS — Create WidgetKit extension (Swift)
In Xcode: File → New Target → Widget Extension. Name: QuranWidget. Reads shared UserDefaults (App Group: group.com.yourcompany.quran). Implement Small and Medium widget families. Use SwiftUI Text with Arabic locale for RTL rendering.
Android — Create Glance AppWidget (Kotlin)
Create android/app/src/main/kotlin/…/QuranWidget.kt extending GlanceAppWidget. Reads data from HomeWidgetPlugin.getData(). Define QuranWidgetReceiver, register in AndroidManifest.xml with <receiver> and widget XML layout metadata.
Wire background refresh
Register HomeWidget.registerBackgroundCallback(backgroundCallback) in main.dart. The backgroundCallback is a top-level function that calls QuoteService.getOrRefreshDailyQuote() and WidgetDataService.push(). iOS uses Background App Refresh; Android uses WorkManager via the plugin.
Handle widget tap → deep link
iOS: Set Link in SwiftUI view to quran://quote. Android: Set android:onClick to launch the app with action extra. Flutter side: handle HomeWidget.widgetClicked stream to navigate to the QuoteCard or the surah's ayah view.
Update widget on quote change
Trigger WidgetDataService.push() from QuoteBloc whenever a new quote is generated (midnight refresh or manual refresh in Settings). Also update the now-playing fields from PlayerBloc when a track starts playing.

// lib/data/services/widget_data_service.dart
class WidgetDataService {
  static const String _appGroupId = 'group.com.yourcompany.quran';
  static const _androidName = 'QuranWidget';
  static const _iosKind    = 'QuranWidget';

  Future<void> push(QuoteModel quote, [Track? nowPlaying]) async {
    await Future.wait([
      HomeWidget.saveWidgetData('quote_arabic',      quote.arabicText),
      HomeWidget.saveWidgetData('quote_translation', quote.translation ?? ''),
      HomeWidget.saveWidgetData('quote_surah',       quote.surahEnglishName),
      HomeWidget.saveWidgetData('quote_ayah_num',    quote.ayahNumber),
      HomeWidget.saveWidgetData('now_playing_surah', nowPlaying?.surah.englishName ?? ''),
    ]);
    await HomeWidget.updateWidget(
      androidName: _androidName,
      iOSName:     _iosKind,
      qualifiedAndroidName: 'com.yourcompany.quran.QuranWidgetReceiver',
    );
  }
}

New Package Dependencies

Core notification scheduling. Supports iOS rich notifications, Android channels, exact time scheduling, and custom payloads for deep linking.

Required by flutter_local_notifications for accurate timezone-aware scheduled notifications (e.g., 7am in the user's local timezone).

Request notification permission on Android 13+ (POST_NOTIFICATIONS) and iOS. Also used to check and redirect to settings if denied.

Cross-platform bridge to native iOS WidgetKit and Android Glance widgets. Handles shared data storage, widget update triggers, and background callbacks.

Android background task scheduler. Used to refresh the widget quote daily even when the app is closed. iOS uses Background App Refresh handled by home_widget directly.
